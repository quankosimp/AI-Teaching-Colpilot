# API contract v1: additive G1 & G2 changes

G1 adds `AuthMockInput`, `AuthResponse`, `TeacherMeResponse`, `StudentRecord`, `StudentResponse`, `StudentListResponse`, `VersionHeader`, and `REPLAY_ROUTES` exports. Existing v1 exports retain their meaning. Mock login accepts only `teacher-a` or `teacher-b` in explicitly permitted local/test mode; it returns `{ accessToken }`, while `GET /auth/me` returns `{ teacher, featureFlags }`.

Student creation accepts `StudentInput` without UI-specific initials/color; the server derives defaults. PATCH student/session and PUT activities require a positive `If-Match-Version`. Idempotent creation routes require `Idempotency-Key` and replay the same resource, never raw credentials or signed URLs. `GET /materials/:id/read-url?version=N` returns a short-lived URL for an authorized ready material version.

G2 adds classroom admission, realtime, learning tools, and review contracts (`InvitePreviewInput`, `InvitePreviewResponse`, `StudentRefreshInput`, `StudentAuthResponse`, `AdmitCommand`, `ClassroomStatePatch`, `QuickCheckStatusUpdate`, `CheckResponseReviewInput`, `EvidenceUpdateInput`, `ClaimDraftInput`, and extended `StudentBoardCommand` operations `clearOwnStrokes`, `setNote`, `setShared`). Student grants use short-lived access JWTs plus revocable `StudentRoomSession` refresh tokens independent of invite rotation after consent/admission, while explicit revocation invalidates all member grants and active `/classroom` sockets. Student submission uploads use student-and-session-scoped `UploadIntent` records (`purpose: "submission"`).

G2 privacy hardening: annotation sources used as student observations are bound to the attributed student. Existing annotations are backfilled only when their evidence identifies one student; unattributed or ambiguous annotations cannot serve as a student's observation. Submission responses omit internal `storageKey`; authorized clients use the existing short-lived read URL endpoint. Legacy generated activity titles derived from claims are sanitized in student room projections.

Student room state adds optional `capabilities.boardWrite`, computed from the live session and the current member's board permission. Clients should treat its absence as no board write capability; the server still enforces permission on every command. Quick-check response sources now carry a version that changes when review feedback or support changes.

Corrective migrations do not trust ownership inferred from historical annotation evidence. They clear uncertain bindings and move dependent approved claims to pending with revision and audit records, reopening reviewed sessions while preserving their end time. Historical approved claims using duplicate observations of the same submission or check response are also moved to pending for human verification.
