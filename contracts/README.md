# API contract v1: additive G1 & G2 changes

Lesson preparation (2026-11-06): `ActivityInput.duration` now permits null/omission for an unestimated activity; existing numeric timings are preserved. `StudentActivity.duration` also permits null. Consumers must sum only specified durations. `materialStartPage` is a zero-based bookmark (default 0, bounded 0–9999), tied to the activity's pinned material version; detaching/changing a material resets it. The viewer selects actual available pages. This is a starting-page bookmark, not an enforced PDF page range or AI extraction. Starting a session or selecting a different activity opens its bookmark unless the command explicitly selects a page. `description` is student-visible content; `teacherNotes` remains teacher-only and is excluded from the student room projection. Migration `202611060003_lesson_content` is additive and makes duration nullable without replacing existing values. `StudentRecord.linkVersion` recognizes the pre-existing student-link version in teacher responses.

G1 adds `AuthMockInput`, `AuthResponse`, `TeacherMeResponse`, `StudentRecord`, `StudentResponse`, `StudentListResponse`, `VersionHeader`, and `REPLAY_ROUTES` exports. Existing v1 exports retain their meaning. Mock login accepts only `teacher-a` or `teacher-b` in explicitly permitted local/test mode; it returns `{ accessToken }`, while `GET /auth/me` returns `{ teacher, featureFlags }`.

Student creation accepts `StudentInput` without UI-specific initials/color; the server derives defaults. PATCH student/session and PUT activities require a positive `If-Match-Version`. Idempotent creation routes require `Idempotency-Key` and replay the same resource, never raw credentials or signed URLs. `GET /materials/:id/read-url?version=N` returns a short-lived URL for an authorized ready material version.

G2 adds classroom admission, realtime, learning tools, and review contracts (`InvitePreviewInput`, `InvitePreviewResponse`, `StudentRefreshInput`, `StudentAuthResponse`, `AdmitCommand`, `ClassroomStatePatch`, `QuickCheckStatusUpdate`, `CheckResponseReviewInput`, `EvidenceUpdateInput`, `ClaimDraftInput`, and extended `StudentBoardCommand` operations `clearOwnStrokes`, `setNote`, `setShared`). Student grants use short-lived access JWTs plus revocable `StudentRoomSession` refresh tokens independent of invite rotation after consent/admission, while explicit revocation invalidates all member grants and active `/classroom` sockets. Student submission uploads use student-and-session-scoped `UploadIntent` records (`purpose: "submission"`).

G2 privacy hardening: annotation sources used as student observations are bound to the attributed student. Historical inferred owners are cleared by corrective migrations because old evidence cannot prove original annotation ownership; unattributed or ambiguous annotations cannot serve as a student's observation. Submission responses omit internal `storageKey`; authorized clients use the existing short-lived read URL endpoint. Legacy generated activity titles derived from claims are sanitized in student room projections.

Student room state adds `capabilities` (`boardWrite`, `upload`, `check`, `chat`), dynamically computed from the live session status, joined member state, valid grant, session tool configuration, and individual member tool overrides. Board write additionally requires member board write permission. Malformed session tools default to deny all capabilities. `StudentRoomViewModel.annotations` provides safe mark projections (`id`, `page`, `x`, `y`, `text`) scoped to the active activity, material version, and current page; students see only their own annotations or annotations explicitly marked `sharedWithClass`. Attributed student annotations cannot be shared with the class.

Corrective migrations do not trust ownership inferred from historical annotation evidence. They clear uncertain bindings and move dependent approved claims to pending with revision and audit records, reopening reviewed sessions while preserving their end time. Historical approved claims using duplicate observations of the same submission or check response (including those where duplicate copies were soft-deleted) are conservatively moved to pending for human verification. Source regrading distinguishes auto-generated grade evidence (`isAuto: true`) from independent manual observations, preserving manual observation content and support without advancing its source version while reopening dependent claims.

G4 adds AI teaching assistance and claim drafting contracts (`TeachingRequestMode`, `AIRequestInput`, `AIStatusUpdate`, `AIClaimsDraftInput`, `AISuggestionItem`, `AISuggestionResponse`, `AIStatusUpdateResponse`, `AIClaimCandidate`, `AIClaimsDraftResponse`, `AICircuitStatusResponse`).
- In-session suggestions support 4 request modes: `explain`, `leading_question`, `example`, and `difficulty`, bounded strictly to targeted student and current activity context with explicit student consent.
- Suggestion lifecycle tracks `ready` -> `used`, `ignored`, or `reported` with optional teacher text corrections (`editedText`). Used suggestions can optionally be persisted as `Evidence` with `isObservation: false` (`kind: "GoiYGiangDay"`, `sourceType: "ai_suggestion"`), preserving prompt, response, model, version, and actor metadata without fabricating competence observations.
- Post-session claim drafting produces pending claims linked strictly to valid active observation evidence belonging to the student; sessions without observations return zero claims. All evidence references and source versions are revalidated under session lock after provider execution.
- AI requests are guarded by circuit breaker and bounded timeouts, sanitizing all tokens, secrets, signed URLs, and student PII from provider contexts and error messages. Provider labeling honestly identifies `gemini` versus guarded local/test `mock` execution.

Supervisor integration corrections: migration 008 is restored byte-for-byte to its already-applied form; migration 009 adds teaching modes and 010 adds durable plan source references. Claim drafting stores an immutable response receipt (including an empty model result), accepts only references present in the dispatched snapshot, and bounds observations to 20. Replays preserve the original pending draft or plan provenance without another provider call. Historical plan requests without a source snapshot return a conflict requiring a new request. Suggestion lifecycle retries with the same final content/status reuse the existing teaching aid. Student views and sockets never receive these private AI records.

G3 local media: the real adapter uses the supported Zoom Toolkit preview and native mic/camera/share toolbar. Wrapper device buttons are local simulation only; real SDK state comes from joined/connection and typed participant events. Opening a preview does not mark the session connected. Session creation/teardown is serialized across room components, with abort signals for delayed requests. Tokens are minted and audited under the session lock after current ownership, grant, admission and live-state checks. Real Zoom and Gemini acceptance still requires actual credentials and provider runs.
